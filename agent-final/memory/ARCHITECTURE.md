## Architectural Layers & Rules

> These rules are enforced by `/audit` and `check_arch.sh`.

### Layer 1: Domain (Pure Business Logic)
- **Path:** `[source]/features/*/domain/`
- **Allowed imports:** Only standard library + other domain files
- **Forbidden:** Framework imports, network libs, database libs, UI packages
- **Rule:** If you need to import `package:flutter` → you're in the wrong layer

### Layer 2: Data (External Integration)
- **Path:** `[source]/features/*/data/`
- **Allowed imports:** Domain layer + network + database packages
- **Forbidden:** UI packages, presentation layer
- **Rule:** Data layer implements Domain interfaces — never the reverse

### Layer 3: Presentation (UI)
- **Path:** `[source]/features/*/presentation/`
- **Allowed imports:** Domain layer + UI framework + state management
- **Forbidden:** Direct data layer imports (must go through domain)
- **Rule:** UI calls use cases, not repositories directly

## Approved Patterns

> These are the canonical patterns for this project. When in doubt, follow these.

### Dependency Injection

```dart
// ✅ APPROVED: Constructor injection via @injectable
@Injectable()
class GetPhotosUseCase {
  final PhotoRepository _repository;
  GetPhotosUseCase(this._repository);
}

// ❌ FORBIDDEN: Manual GetIt calls in business logic
final service = GetIt.I<MyService>(); // Don't do this outside di/ folder
```

### State Management

```dart
// ✅ APPROVED: BLoC/Cubit with Freezed states
@freezed
class FeatureState with _$FeatureState {
  const factory FeatureState.initial() = _Initial;
  const factory FeatureState.loading() = _Loading;
  const factory FeatureState.success(List<Item> items) = _Success;
  const factory FeatureState.error(String message) = _Error;
}

// ❌ FORBIDDEN: Raw setState for complex logic
setState(() { _items = newItems; }); // Only OK for trivial local UI state
```

### Error Handling

```dart
// ✅ APPROVED: Result type for use case returns
Future<Result<List<Photo>>> call(params) async {
  try {
    final data = await _repository.fetch(params);
    return Success(data);
  } catch (e) {
    return Failure(e.toString());
  }
}
```

## Anti-Patterns (Forbidden)

| Anti-Pattern | Why Forbidden | Correct Approach |
|---|---|---|
| Domain imports framework | Breaks pure domain | Use interfaces, inject via DI |
| UI calls repository directly | Bypasses business logic | Go through use case |
| Hardcoded API URLs | Breaks environments | Use config/constants |
| `print()` in production | Log pollution | Use logger package |
| `dynamic` types | Type safety | Use concrete types or generics |
