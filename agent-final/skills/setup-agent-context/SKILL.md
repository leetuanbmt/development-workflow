# Setup Agent Context & Rules (Auto-Discovery)

## Trigger
Use this skill when the user types `/setup` or asks to initialize/setup the agent's project context and rules.

## Objective
Automatically configure the AI agent environment for a project by:
1. Detecting the project tech stack
2. Generating project context
3. Generating architecture and coding rules
4. Synchronizing agent memory

## Input Schema
The skill leverages the project workspace containing files such as:
- `pubspec.yaml`
- `package.json`
- `requirements.txt`
- `README.md`
- Requirement documents
- Source code folders

## Execution Flow

### 1. Discovery & Analysis

Determine whether the project is a Brownfield or Greenfield project.

#### Case A — Brownfield Project (Existing Code)
**Actions:**
Scan configuration files (e.g., `pubspec.yaml`, `package.json`, `requirements.txt`, `go.mod`, `pom.xml`) using workspace inspection tools.

**Detect:**
- Programming language
- Framework
- Dependency libraries
- Project architecture patterns

**Evaluate:**
- Project structure
- Existing architecture patterns
- Code quality indicators

#### Case B — Greenfield Project (New Project)
**Condition:** The project directory is empty or contains only requirement files.

**Actions:**
1. Ask the user: *"What type of system are you building?"* (Examples: Mobile Application, Backend API, Web Platform, CLI Tool, AI Tool).
2. Use Tech Lead reasoning to suggest an appropriate stack based on user input. For example:
   - Mobile → Flutter
   - Backend → Node.js / FastAPI
   - Fullstack → Next.js
   - Tooling → Python
3. Run the following command: `scripts/sync.sh --stack=<suggested_stack>`
4. (Optional) Suggest a project initialization command (e.g., `flutter create app`, `npm init`, `fastapi startproject`).

### 2. Generate Project Context

Create the project context documentation and save it to `rules/01-project-context.md`.

**Template constraint:**
Use the exact template below for the output file:

```markdown

> **Last Updated:** [date]
> **Auto-generated by:** `/setup`

## 1. Overview
- **Project Name:** [Project Name]
- **Short Description:** [Short Description]
- **Primary Language:** [Primary Language]

## 2. Tech Stack
- **Framework:** [Framework]
- **State Management:** [State Management]
- **Architecture Pattern:** [Architecture Pattern]
- **Dependency Injection:** [Dependency Injection]
- **Networking:** [Networking]

- **Run Dev:** [Command]
- **Code Generation:** [Command]

- **Lint:** [Command]
- **Build:** [Command]

## 4. Project Structure
- **Entry Point:** [Entry Point Path]
- **Feature Folder:** [Feature Folder Path]

- **Infrastructure Layer:** [Infrastructure Layer Path]
```

### 3. Generate Dynamic Rules

Based on the detected tech stack, generate architecture and coding standard rules and save them to `rules/02-architecture-rules.md`.

**Branch logic:**
- **Mobile (Flutter / React Native):**
  Generate rules for Clean Architecture, Feature-first structure, State management patterns, and Code generation conventions. Adjust rules dynamically based on detected libraries.
- **Node.js Backend:**
  Generate backend architecture rules covering Controller, Service, and Repository patterns. Add rules for API validation, error handling, logging, and dependency injection.
- **Python:**
  Generate coding rules based on PEP8, project module structure, and testing practices.

*Important:* Avoid hardcoding specific frameworks unless they are explicitly detected in the workspace.

### 4. Sync Agent Memory

Synchronize the generated files into the agent's memory to ensure pervasive context.

**Actions:**
1. Copy `rules/01-project-context.md` to `.agent/memory/PROJECT.md`.
2. Update `.agent/memory/ARCHITECTURE.md` with the content generated in step 3.
3. (Optional) Reload environment by running: `bash scripts/sync.sh`

## System Prompt

You are an AI Architect responsible for initializing AI agent project contexts. Always follow the Execution Flow meticulously. Execute discovery efficiently, prompt the user if needed for Greenfield projects, format output precisely as specified, generate accurate architecture rules dynamically derived from the stack, and ensure memory paths are synchronized. Always keep `PROJECT.md` and `ARCHITECTURE.md` synchronized with agent memory.

**User:** `/setup`

**Agent Action 1:** Scans workspace, finds `package.json` with React and Express. This is a Brownfield project.
**Agent Action 2:** Generates `rules/01-project-context.md` with React + Express details.
**Agent Action 3:** Generates `rules/02-architecture-rules.md` for Node.js backend and React frontend.
**Agent Action 4:** Copies `rules/01-project-context.md` to `.agent/memory/PROJECT.md` and updates `.agent/memory/ARCHITECTURE.md`.
**Agent Output:** Communicates completion of context generation, tech stack detection, and memory synchronization to the user.
